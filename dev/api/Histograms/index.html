Histograms

The summary types: Histogram1D and Histogram2D — finely binned empirical measures that fold the stream into a fixed-size form — plus bin_index and observe_pairs! for two-time statistics.

Summaries

GBGStreamingStatistics.Histograms.Histogram1D — Type
Histogram1D <: AbstractAccumulator
Histogram1D(lower, upper, nbins; order = 4, accumulator = Float64, count = UInt64)

A finely binned empirical measure of a conditioning variable $X$ — the canonical summary $T(\hat\mu_n)$. nbins equal-width (WARPing) bins tile the half-open range $[\texttt{lower}, \texttt{upper})$; choosing the range to cover the data (e.g. $\pm 5\sigma$ for the data's standard deviation $\sigma$) with $\gtrsim 10^3$ bins makes the bin width $b \approx \sigma/100$ far below any post-hoc smoothing bandwidth $h$ ($b \ll h$), so the summary is approximately sufficient.

Each bin carries its count and the power-sums $S_p = \sum_{i \in \text{bin}}(X_i - c_j)^p$ about the fixed bin center $c_j$, for $p = 1 \dots \texttt{order}$. Because $X_i - c_j$ is small within a bin these are well-conditioned, so accumulation is a plain atomic scatter-add (observe!) that runs identically on CPU and GPU, and merge! is elementwise addition. The power-sums use the actual $X_i$ (not the center), so the global central moments recovered post hoc (by the shift formula) are exact, and stable for the even orders (the odd orders, $\approx 0$, keep weaker relative precision). The default order = 4 recovers up to $M_4$; an even higher moment such as $M_6$ needs order = 6. Counts are UInt64 by default (the additive monoid) and power-sums are accumulated in accumulator (Float64 by default) regardless of the input element type — accumulate wider than the data. Set count = Float64 for the Float-count variant that scale! and weighted merge! require — the cone the hyperstatistical parameter-mixture and exponential forgetting are built from (a fractional weighted count is not an integer).

Samples outside $[\texttt{lower}, \texttt{upper})$ are skipped (not counted) — set the range to cover the data.

Fields

The summary's whole state, each reachable by dot — summary.lower, summary.scale, summary.counts, … — for serialization, inspection, or building one by hand:

  • lower, upper — the range edges (upper > lower).
  • scale — the precomputed binning factor nbins / (upper - lower), stored (not recomputed) so that bin_index is a single multiply.
  • counts — per-bin counts, length nbins (UInt64, or the count type; nbins == length(counts)).
  • powersums — per-bin power-sums, $\texttt{order} \times \texttt{nbins}$ (row $p$ is $S_p$; order == size(powersums, 1)).

A freshly constructed summary is empty: counts and powersums are all zeros (the merge! identity), and you observe! data into it. merge! adds counts and powersums elementwise, so summaries on the same binning combine by saving and adding these two arrays. The recovered moments are read out with mean, var, std, and central_moment.

GBGStreamingStatistics.Histograms.Histogram2D — Type
Histogram2D <: AbstractAccumulator
Histogram2D(xlower, xupper, nx, ylower, yupper, ny; lag = 0,
            accumulator = Float64, count = UInt64)

A joint binned empirical measure of $(X, Y)$ — one per lag $\tau$ — for conditional and two-time transition densities. $\texttt{nx} \times \texttt{ny}$ equal-width cells tile $[\texttt{xlower}, \texttt{xupper}) \times [\texttt{ylower}, \texttt{yupper})$; each cell (ix, iy) (flattened ix + (iy-1)*nx) carries its count and the order-2 bivariate power-sums $S_{rs} = \sum_{(X,Y)\in\text{cell}} (X - c^x)^r (Y - c^y)^s$ about the cell center $(c^x, c^y)$ — $S_{10}, S_{01}, S_{20}, S_{11}, S_{02}$ — the local sufficient statistic for the joint density and for local-linear conditioning. For a two-time quantity $X(t)$ and the response $Y(t+\tau)$ are paired per source; the lag $\tau$ is an explicit label on the summary. Pairs outside the box are skipped. Same atomic-scatter accumulation, merge!-by-addition, Float64 accumulation, and count = Float64 Float-count / cone variant (for scale! and weighted merge!) as Histogram1D.

Fields

The summary's whole state, each reachable by dot (summary.xlower, summary.xscale, summary.lag, …):

  • xlower, xupper, ylower, yupper, nx, ny — the box and cell counts.
  • xscale, yscale — the precomputed binning factors nx/(xupper-xlower), ny/(yupper-ylower), stored.
  • lag — the lag $\tau$ this joint summary is accumulated at (0 for the static joint).
  • counts — per-cell counts, length nx*ny (cell (ix, iy) at ix + (iy-1)*nx; UInt64, or the count type).
  • powersums — $5 \times (\texttt{nx} \cdot \texttt{ny})$: rows $S_{10}, S_{01}, S_{20}, S_{11}, S_{02}$ about the cell center.

A freshly constructed summary is empty (counts, powersums all zeros). merge! adds counts and powersums (requires matching box, cell counts, and lag).

Accumulation

observe! / merge! are the universal Accumulators interface; observe_pairs! folds two-time pairs into a Histogram2D, and bin_index exposes the binning map.

GBGStreamingStatistics.Histograms.observe_pairs! — Function
observe_pairs!(summary::Histogram2D, x_past, y_now) -> summary

Fold a batch of pre-formed pairs $\bigl(X(t),\, Y(t+\tau)\bigr)$ into the per-lag summary in place (x_past holds $X(t)$, y_now holds $Y(t+\tau)$, equal length) — the memoryless surface for two-time statistics. The pairs are binned by an atomic scatter-add (one work-item per pair, CPU and GPU alike); everything that produces the pairs — the snapshot buffer of past $X(t)$, which sources to sample, which lags to form, the origin cadence — is the consumer's responsibility, formed at the summary's lag $\tau$.

GBGStreamingStatistics.Histograms.bin_index — Function
bin_index(summary, x) -> i

The binning map: the index $i$ of the bin containing x. For a Histogram1D over $[\texttt{lower}, \texttt{upper})$ with nbins bins, $i = \lfloor (x - \texttt{lower})\,\texttt{scale} \rfloor + 1$; a valid bin satisfies $1 \le i \le \texttt{nbins}$, and x outside the range yields $i < 1$ or $i > \texttt{nbins}$. Exposed so a consumer can pre-quantize a snapshot buffer (e.g. store compact UInt16 bin indices) before forming lagged pairs for observe_pairs!.

Recovered moments

The global marginal moments, recovered post hoc from the power-sums by the shift formula (exact), extending Statistics.

Statistics.mean — Method
mean(summary::Histogram1D)

Estimand. the population mean $\mathbb{E}[X]$.

Estimator. the sample mean $\bar X = \frac1n \sum_i X_i$ — recovered exactly (not a smoothed estimate) host-side from the per-bin counts and first power-sums by the shift formula (the power-sums use the actual $X_i$, not the bin center). Extends Statistics.mean; an empty summary gives NaN.

source
Statistics.var — Method
var(summary::Histogram1D; corrected = true)

Estimand. the population variance $\operatorname{Var}(X) = \mathbb{E}\bigl[(X - \mathbb{E}[X])^2\bigr]$.

Estimator. the recovered sample variance ($\bar X$ the recovered mean). With corrected = true (the default, matching Statistics.var) the unbiased $\frac{1}{n-1} \sum_i (X_i - \bar X)^2$ (Bessel's correction; NaN for $n \le 1$); corrected = false the $\frac1n \sum_i (X_i - \bar X)^2$ order-2 central moment (central_moment at $p = 2$). Exact via the shift formula. Extends Statistics.var.

source
Statistics.std — Method
std(summary::Histogram1D; corrected = true)

Estimand. the population standard deviation $\sigma = \sqrt{\operatorname{Var}(X)}$.

Estimator. the recovered sample standard deviation $\sqrt{s^2}$, where $s^2$ is the recovered variance (var); the corrected keyword has the same meaning (the default true divides by $n - 1$). Exact via the shift formula. Extends Statistics.std.

source
GBGStreamingStatistics.Histograms.central_moment — Function
central_moment(summary::Histogram1D, p)

Estimand. the population $p$-th central moment $\mu_p = \mathbb{E}\bigl[(X - \mathbb{E}[X])^p\bigr]$.

Estimator. the sample central moment $\frac1n \sum_i (X_i - \bar X)^p$ ($\bar X$ the recovered mean), recovered exactly from the power-sums by the shift formula — not a smoothed estimate — for $2 \le p \le \texttt{order}$. $p = 2$ is the uncorrected variance (var with corrected = false); even orders recover stably, odd orders ($\approx 0$) to weaker relative precision.
